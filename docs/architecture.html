WebFind Architecture

Google-inspired 3-phase crawl engine: Discover the link graph (depth-aware BFS), Prioritize URLs by hop depth, Fetch top-scored pages with per-host politeness and proxy rotation. Six MCP tools, two storage backends, ranked JSON output.

System Architecture

HLD (right): LLM calls 6 MCP tools — search queries the index, research crawls + indexes + queries, fetch extracts one URL, graph traverses edges.
LLD (center): 3-phase crawl engine — Discovery BFS with depth tracking, Priority Scoring, Budget-Constrained Fetch — plus identity rotation, extraction, and storage.

Phase 1 — Discover

BFS through the link graph from seed(s). Each URL is tagged with depth (hop count from seed). Internal links stay on-domain; external links are followed when follow_external=true. Discovery stops at max_depth (default 5). Sitemap entries seed the queue at depth 1.

2

Phase 2 — Prioritize

Each discovered URL is scored: 1 / (1 + depth). URLs at or below min_depth (default 3) are force-fetched regardless of budget. The queue is sorted shallowest-first — Google's insight that click depth determines crawl priority, not URL path depth.

3

Phase 3 — Fetch

Top-scored URLs are fetched within the max_pages budget. Per-domain politeness enforced via robots.txt crawl-delay + RPS limiter. Each CrawlSession gets a rotating proxy, random DeviceProfile, and cookie jar. Dynamic Chromium fallback for JS-heavy pages.

4

Enrich, Index & Rank

Fetched pages become StructuredContent with keywords, depth metadata, and link edges written to CrawlGraphStore. Indexed in Tantivy (BM25) + optional vector engine. Ranker merges BM25, dense vector, and PageRank scores into a ranked JSON response.

Key Design Decisions

Depth = hop count, not URL path. Google's insight: a page at /api/v2/docs/detail linked from the homepage has depth 1, not 4. Depth is tracked on the BFS queue as (url, depth) tuples.
min_depth forces deep crawling. Default 3 ensures the crawler reaches past landing pages to API docs, reference pages, and detail content that lives 3+ hops from the seed.
External links get lower priority. Cross-domain links are discovered at ExternalLink source with priority 0.3 (vs 0.5 for internal). They're followed but deprioritized in the fetch budget.
6 MCP tools, not 4. search (index query), research (crawl+search), research_parallel (multi-seed), fetch (single URL), fetch_parallel (batch), graph (traverse edges).
