WebFind Architecture

SurrealDB-first search architecture. /search queries URLs already stored in the knowledge graph and re-fetches them for fresh content. /research discovers and crawls URLs that are not already in the graph, persists them, and returns results. All data lives in SurrealDB; no local Tantivy index is used in production serve mode.

System Architecture

HLD (left): LLM calls 4 MCP tools over Streamable HTTP. LLD (right): auto-discovery, dual crawl engines, SurrealDB search/rank/store layers.

1

Auto-Discovery

src/engine/discovery.rs runs when webfind_research is called without a seed. It extracts keywords from the query, generates domain candidates (e.g. https://keyword.com), validates them with concurrent DNS + HTTP checks, and returns the best seeds. Includes a hard timeout ceiling and a fallback to the most obvious candidate so research never hangs.

2

BulkDomainCrawler (3-Phase)

src/engine/bulk_crawler.rs is the production crawler. Phase 1 Discover: BFS queue with (url, depth, relevance). Seeds: user URL (depth 0) + sitemap entries (depth 1). Internal links at depth+1; external links at depth+1 with 0.3x priority. Already-crawled URLs in the graph store are skipped. Phase 2 Prioritize: Score = 1/(1+depth) + content relevance, best-first. Phase 3 Fetch: per-domain queue, rate limiter, robots.txt policy, rotating CrawlSession.

3

CrawlGraphStore + PageRank

src/engine/crawl_graph.rs trait with InMemoryCrawlGraph and SurrealDB impl. Records UrlNode (url, domain, source, depth, priority, lastmod, changefreq, crawled flag) and LinkEdge (from, to, anchor_text). Traversal BFS supports inbound/outbound/both. compute_pagerank() is iterative with damping. PageRankCache persists scores keyed by graph version token.

4

Identity & Fingerprint Rotation

src/engine/fetcher.rs + human_client.rs + fingerprint.rs. ProxyPool from user list or CIDR. SessionManager sticky per domain. DeviceProfile randomized UA + headers. FingerprintGenerator creates TLS+HTTP/2 fingerprints. FingerprintAuditLog logs every request to SurrealDB. ip_health tracks proxy health.

5

Fetcher & Extraction

src/engine/fetcher.rs dual path: direct reqwest or HumanClient. Content-type classifier. HTML article extraction via readability_rust + scraper fallback. Metadata: <meta>, OpenGraph, Twitter Card, JSON-LD. Internal/external link split. Language detection (whatlang), readability metrics, RAKE keywords, paywall detection. Optional Chromium dynamic fallback.

6

Search Engine Trait

src/engine/search_engine.rs defines the SearchEngine trait: index_one, index_batch, search_bm25, index_vector, index_vector_batch, search_vector, doc_count, optimize. Two impls: InMemorySearchEngine (tests/local) and SurrealSearchEngine (production, backed by SurrealDB FULLTEXT + HNSW). Indexer wraps the trait.

7

Ranker (Multi-Signal)

src/engine/ranker.rs combines: BM25 (lexical), Freshness (exp decay, 180-day half-life), Quality (Flesch ease + grade level sweet spot), Graph/PageRank (centrality), Vector (cosine similarity, optional). Weights: 0.55/0.20/0.15/0.10 default; hybrid adds vector at 0.20. Also applies domain-diversity penalty and structured-data boost.

8

4 MCP Tools

src/mcp.rs -- webfind_search: query URLs already in SurrealDB, re-fetch them for fresh content. webfind_research: discover/crawl URLs not already in the graph, persist them, return results. webfind_fetch: single URL extract (direct → proxy fallback). webfind_graph: traverse crawl graph from URL. All tools accept timestamp (ISO8601) to inject the current year into queries. Parallel batch tools were removed; use independent native tool calls instead.

9

Background Worker

src/engine/bg_worker.rs receives fetched StructuredContent from the crawler over a bounded async channel. It generates embeddings (FastEmbed), writes a page_content record, creates the url_node -> page_content has_content relation, and updates crawl_job status. The worker is drained before a research response is returned.

10

SurrealDB Schema

schema/init.sql + schema/unified.surql define url_node (metadata + BM25/HNSW), page_content (full text/HTML/markdown), link_edge (directed graph relation), has_content (url → content relation), crawl_job (background queue), and auxiliary tables for fingerprints, ip_health, and graph versioning.

11

Deployment

Dockerfile multi-stage build (planner/builder/runtime). compose.yml runs surrealdb/surrealdb + schema-init (curl) + webfind server on port 4748. Works on Windows (Docker Desktop/WSL2), Linux, and macOS (Docker Desktop/OrbStack). Data persisted in named volumes surreal-data and webfind-data.

Key Design Decisions

SurrealDB is the single source of truth. Both /search and /research read/write the same SurrealDB instance. No Tantivy index is used in production serve mode.
/search vs /research separation. /search only re-fetches URLs already present in the graph. /research only discovers and fetches URLs not yet crawled/persisted.
Seed is optional for research. When omitted, auto-discovery generates and validates candidates from the query itself. Explicit seeds still skip URLs already marked crawled=true.
External links get lower priority. Cross-domain links are recorded as ExternalLink with 0.3x priority. Followed only if follow_external=true.
Background persistence decouples crawl from storage. The crawler hands content to BackgroundWorker, which writes the full knowledge graph asynchronously while the request continues.
Graph version token for PageRank cache. graph_meta:version increments on every mutation. PageRankCache stores scores keyed by version; recomputes only when the graph changes.
Timestamp injection for current-year queries. All MCP tools accept timestamp (ISO8601). If the query lacks a 4-digit year, the current year is appended.
Proxy support everywhere fetches happen. Both /search and /research accept a comma-separated proxies parameter; webfind_fetch also falls back through proxies on direct failure.

Data Flow Summary

Research Flow
  1. LLM calls webfind_research(seed?, query, ...)
  2. If no seed: discovery.rs validates query-derived candidates
  3. BulkDomainCrawler skips URLs already crawled=true in SurrealDB
  4. Discover → Prioritize → Fetch new URLs
  5. Fetcher extracts StructuredContent
  6. URLs + edges recorded to CrawlGraphStore (SurrealDB)
  7. Content queued to BackgroundWorker for page_content + embeddings
  8. Freshly crawled content ranked and returned as JSON
Search Flow
  1. LLM calls webfind_search(query, hybrid, graph)
  2. SurrealSearchEngine.search_bm25 finds known URLs
  3. Top URLs are re-fetched from the internet for fresh content
  4. If hybrid: search_vector adds semantic scores
  5. If graph: PageRankCache.get_or_compute()
  6. Ranker.rank combines signals
  7. SearchResponse JSON returned
